## Things learned that change the plan

1. **`-X perf` is unavailable in the JIT-on arm.** `Python/sysmodule.c` on the 3.15 branch refuses to activate the perf trampoline (either backend) when the JIT is active, and `jit.c` emits no perf map. RQ2 profiling is asymmetric: Python-function attribution in the off arm only; the on arm gives native vs anonymous-JIT time plus pystats executor counts. Plan and analysis README updated.
2. **labeille's `jit_enabled` metadata is always False on 3.15.** `check_jit_enabled` tests `sys.flags.jit`, which does not exist on the 3.15 branch (only `sys._jit.is_available/is_enabled/is_active`). Harmless for the study since our `check_jit` log is the authority, but the run `meta.json` will say "JIT enabled: no" in both arms. Candidate for a one-line labeille patch, filed by Fangchen if at all.
3. **labeille is quiet.** HEAD `58fdf6ab` is from April 2, 2026; laruche HEAD `01d8860a` from July 13. Pin both and patch locally.
4. **Cohort is fully covered by the registry.** All top-25 packages (snapshot 2026-11-01) have laruche entries; 23 use `python -m pytest`, so the JUnit suffix works; pycparser (`unittest discover`) needs `--test-command-override`; pydantic-core has no test command. Registry `skip_versions: 3.15` on numpy, pydantic and pydantic-core predate their cp315 wheels. `compat/cohort.txt` filled as PROPOSED pending the snapshot-date decision.
5. **uv cannot install 3.15.0+ here** (its index stops at 3.15.0b4 in this sandbox), and GitHub release downloads are blocked by the proxy, so the sandbox check used b4. The ABI is frozen from b1, cp315 wheels for pandas 3.1.1, NumPy 2.5.4 and pyarrow 26.0.0 installed and imported fine. The passthrough answer is about asv, not the interpreter, so it stands; the study build re-confirms it on metal.

## asv passthrough evidence

Minimal asv project (`scratchpad/asvcheck`): a benchmark whose `setup()` appends `check_jit`-style state to a log file, and `track_jit_enabled` returning `int(sys._jit.is_enabled())`.

```
arm PYTHON_JIT=0: 3471 setup() calls in 2 benchmark processes; distinct (PYTHON_JIT, available, enabled): {('0', True, False)}
arm PYTHON_JIT=1: 3784 setup() calls in 2 benchmark processes; distinct (PYTHON_JIT, available, enabled): {('1', True, True)}
track_jit_enabled: 0 (off) / 1 (on)
```

Same project with `matrix: {"env": {"PYTHON_JIT": ["0","1"]}}` and `-E existing:`: asv reports "1 environments" and the benchmark process sees `PYTHON_JIT=None`. Env matrix confirmed inert for `existing:`.

Without `--machine` labels the on arm overwrote the off arm's result file (`.asv/results/vm/<commit>-existing-...json`). With `--machine vm-jit-0` / `vm-jit-1`, two files. Those two files are `analysis/testdata/asv/{off,on}.json`.
